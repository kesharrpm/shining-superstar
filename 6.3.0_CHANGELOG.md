# SHINING SUPERSTAR 6.3.0 — Secure Foundation

## Security

- Firebase Authentication is the normal identity/session source.
- Protected save/economy mutations move to an authenticated Cloudflare Worker.
- Strict Firestore rules block direct browser rewriting of protected values.
- Admin routes use a Worker secret and timing-safe token comparison.
- Player/admin CORS is origin-restricted; public catalog assets remain cache-friendly.
- Server-side stage completion computes trusted reward totals from server-held deck state rather than accepting browser currency totals.

## Catalog/Cloudflare

- D1 + published `catalog-assets` becomes the documented canonical catalog architecture.
- Added `/health`, admin status, validation, and asset-contract import.
- Explicit `ASSET_CONTRACT.json` logical bindings are supported.
- Existing aliases and logical fallback remain for compatibility.

## Client

- Split the 6.2 monolithic engine into 11 ordered script modules.
- Added `secure-api.js` as the Auth V3 / Worker bridge.
- Preserved the original monolith in `legacy/` for rollback/reference.

## Asset tooling

- Integrated Catalog Studio/Cloudinary generator as `catalog-studio-v6`.
- Asset contract describes Cloudinary public ID, legacy bundle entry, and runtime logical ID.
- No Cloudinary API secret is stored in browser HTML.

## Administration

- Added standalone catalog admin/validator dashboard.

## Compatibility note

- Chance-based card/pull outcomes are not promoted to trusted server-authoritative economy mutations in this release. Strict mode prevents browser-forged protected state from becoming authoritative.
